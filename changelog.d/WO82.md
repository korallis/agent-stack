### Fixed
- `agent-heavy` recognises a slot's holders on Btrfs. There, `stat` reports the subvolume's device for the lock file
  while `/proc/locks` and fdinfo show the filesystem's, so the device:inode match found no holder. `status` called a
  held slot free, and a nested same-class call didn't recognise its parent: with one slot it waited for itself, and
  with `--wait 0` it exited 75. Holders are now the processes with an fd on the lock's real path that carries the
  FLOCK; no device numbers are compared. A lock the table shows without a visible holder (matched by device:inode, or
  by inode when the devices differ) is still "owner unknown", never free.
