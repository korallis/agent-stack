### Changed
- `agent-heavy` waiters are served first come, first served. Before, every waiter polled each slot every 5 s, so a freed
  slot went to whichever polled first and an urgent QA run waited ~20 minutes while newer jobs won. Each waiter now takes
  a ticket in the slot dir (arrival, pid, priority) and may try a slot only while it is among the first K live tickets
  (K = free slots); a dead waiter's ticket (pid gone or reused) is skipped and removed. `--priority urgent|critical`
  (or `AGENT_HEAVY_PRIORITY`) sorts ahead of routine, for critical-path QA and merge-gate re-runs; it only orders the
  queue and never preempts a running job; the resolved lane (flag over env) is exported, so nested calls inherit it. `agent-heavy status` lists the queue (position, seat, priority, waiting
  time). Nested inline calls, `--wait`/exit 75 and the max runtime are unchanged.
